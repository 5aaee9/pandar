# Frontend Root Monorepo Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move frontend npm package management to the repository root, align shared frontend dependencies, and remove the narrow duplicate utility code without changing runtime behavior.

**Architecture:** Introduce a private root npm workspace containing `pandar-web`, `pandar-auth`, and `pandar-plugin-local`. Keep the three existing package directories and app boundaries, but replace nested lockfiles with one root `package-lock.json`. Update Nix and Docker to build selected workspaces from the root lockfile while still installing separate `pandar-web` and `pandar-auth` runtime outputs.

**Tech Stack:** npm workspaces, Next.js 16, React 19, Tailwind CSS 4, Vitest, Nix `buildNpmPackage`, Docker, Rust Cargo verification.

## Global Constraints

- Root npm workspaces must be exactly `frontend`, `frontend/auth`, and `frontend/plugin-local`.
- The only npm lockfile after implementation is root `package-lock.json`; delete `frontend/package-lock.json` and `frontend/auth/package-lock.json`.
- Do not add a shared frontend package.
- Do not merge dashboard and auth shadcn primitives unless a primitive is proven equivalent and can be shared without changing its public contract.
- `frontend/auth/lib/utils.ts` must become `export { cn } from "../../lib/utils";`.
- `frontend/package.json` must not declare `workspaces`; its `build` script must build only the dashboard Next.js app.
- Root `build:web` must run plugin-local first, then build `pandar-web`.
- Exact shared dependency versions must be aligned for `next`, `react`, `react-dom`, `typescript`, `@types/node`, `@types/react`, `@types/react-dom`, `class-variance-authority`, `clsx`, `lucide-react`, `tailwind-merge`, and `vitest`.
- `tailwindcss` and `@tailwindcss/postcss` must align to the newer existing auth toolchain version if both apps build cleanly; do not downgrade Tailwind solely to match the dashboard app.
- Any dependency exception must be recorded in `docs/roadmap.md` with package name, app, retained version, and verification reason.
- Nix `pandar-web` and `pandar-auth` must build from the root lockfile and selected npm workspace; refresh both `npmDepsHash` values.
- `pandar-auth` Nix install must create `$out/share/pandar-auth/migrate-src` with resolvable `./lib/utils.ts` cross-app re-export target at `$out/share/pandar-auth/lib/utils.ts`.
- Web Docker builds in `.github/workflows/docker.yml`, `docker-compose.postgres.yml`, and `docker-compose.sqlite.yml` must use repository-root context and `frontend/Dockerfile`.
- Update `README.md`, `docs/development.md`, and `docs/roadmap.md` for the new root npm workflow.
- Run or record blockers for `npm` tests/builds, Nix web/auth/smoke checks, `cargo fmt`, `cargo clippy`, `cargo nextest run --manifest-path "Cargo.toml" --workspace`, and `git status --short`.
- Keep changes scoped to frontend package management, packaging integration, duplicate utility cleanup, and required docs.

```nix
      frontendWorkspaceRoot = toString root;
      frontendWorkspaceSource = lib.cleanSourceWith {
        src = root;
        filter =
          path: type:
          let
            relativePath = lib.removePrefix "${frontendWorkspaceRoot}/" (toString path);
            isGenerated =
              relativePath == "node_modules"
              || lib.hasPrefix "node_modules/" relativePath
              || relativePath == ".next"
              || lib.hasPrefix ".next/" relativePath
              || relativePath == "frontend/node_modules"
              || lib.hasPrefix "frontend/node_modules/" relativePath
              || relativePath == "frontend/.next"
              || lib.hasPrefix "frontend/.next/" relativePath
              || relativePath == "frontend/out"
              || lib.hasPrefix "frontend/out/" relativePath
              || relativePath == "frontend/tsconfig.tsbuildinfo"
              || relativePath == "frontend/auth/node_modules"
              || lib.hasPrefix "frontend/auth/node_modules/" relativePath
              || relativePath == "frontend/auth/.next"
              || lib.hasPrefix "frontend/auth/.next/" relativePath
              || relativePath == "frontend/auth/out"
              || lib.hasPrefix "frontend/auth/out/" relativePath
              || relativePath == "frontend/auth/tsconfig.tsbuildinfo"
              || relativePath == "frontend/plugin-local/node_modules"
              || lib.hasPrefix "frontend/plugin-local/node_modules/" relativePath
              || relativePath == "frontend/plugin-local/tsconfig.tsbuildinfo";
          in
          !isGenerated
          && (
            relativePath == "package.json"
            || relativePath == "package-lock.json"
            || relativePath == "frontend"
            || lib.hasPrefix "frontend/" relativePath
          );
      };
      frontendSource = "${frontendWorkspaceSource}/frontend";
```

Keep `frontendSource` because the existing cookie and redirect smoke checks run web scripts from the dashboard workspace directory. The broad `frontend/` include intentionally keeps checked-in `frontend/plugin-local/dist/` assets while the generated-output filter excludes plugin-local local build state such as `node_modules` and `tsconfig.tsbuildinfo`.
