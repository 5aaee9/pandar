# Pandar Auth Magic Link And Optional Passkey Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `frontend/auth` use email magic links by default, with optional post-login passkey binding and Resend/SMTP email delivery.

**Architecture:** Keep `frontend/auth` as the Better Auth issuer and keep `frontend`/`pandar-hub` JWT handoff unchanged. Add a focused mailer boundary, replace pre-auth passkey signup with magic-link sign-in, and keep optional passkey setup on `/auth/complete`. NixOS and docs expose non-secret email configuration while secrets remain in `environmentFile`/`extraEnvironment`.

**Tech Stack:** Next.js 16 App Router, React 19, Better Auth 1.6.22, `@better-auth/passkey`, Better Auth magic-link plugin, shadcn `login-05`, Resend HTTP API, Nodemailer SMTP, NixOS module options.

- [ ] **Step 2: Add build/runtime validation helpers**

Use the existing build detection pattern from `readSecret()`. Email provider settings are required when not building. During build, use a dummy Resend config so `next build` can import `auth.ts` without real secrets:

```ts
function isBuild(): boolean {
  return process.env.npm_lifecycle_event === "build";
}

function readRequiredRuntimeString(name: string): string {
  const value = process.env[name]?.trim();
  if (value) {
    return value;
  }
  if (isBuild()) {
    return `build-${name.toLowerCase()}`;
  }
  throw new Error(`${name} is required`);
}
```

Do not suppress invalid configured values. If `PANDAR_AUTH_EMAIL_PROVIDER` is set to anything except `resend` or `smtp`, throw in all modes.

- [ ] **Step 3: Parse email config**

Implement:

```ts
function readEmailConfig(): Env["email"] {
  const provider = process.env.PANDAR_AUTH_EMAIL_PROVIDER?.trim();
  const brandName = readString("PANDAR_AUTH_EMAIL_BRAND_NAME", "Pandar");

  if (!provider && isBuild()) {
    return {
      provider: "resend",
      from: "Pandar <build@example.invalid>",
      brandName,
      apiKey: "build-resend-api-key",
    };
  }

  if (provider === "resend") {
    return {
      provider,
      from: readRequiredRuntimeString("PANDAR_AUTH_EMAIL_FROM"),
      brandName,
      apiKey: readRequiredRuntimeString("RESEND_API_KEY"),
    };
  }

  if (provider === "smtp") {
    return {
      provider,
      from: readRequiredRuntimeString("PANDAR_AUTH_EMAIL_FROM"),
      brandName,
      host: readRequiredRuntimeString("PANDAR_AUTH_SMTP_HOST"),
      port: readRequiredRuntimePositiveInteger("PANDAR_AUTH_SMTP_PORT"),
      username: readRequiredRuntimeString("PANDAR_AUTH_SMTP_USERNAME"),
      password: readRequiredRuntimeString("PANDAR_AUTH_SMTP_PASSWORD"),
      tls: readSmtpTlsMode(),
    };
  }

  throw new Error("PANDAR_AUTH_EMAIL_PROVIDER must be resend or smtp");
}
```

If `PANDAR_AUTH_SMTP_PORT` is missing at runtime, treat it as required instead of silently defaulting. Use a helper that allows the build dummy case but requires runtime values.

- [ ] **Step 4: Create email content and senders**

```ts
import nodemailer from "nodemailer";

import type { env } from "./env.ts";

type EmailConfig = typeof env.email;

type MagicLinkEmail = {
  config: EmailConfig;
  to: string;
  url: string;
  ttlSeconds: number;
};

export function magicLinkSubject(brandName: string): string {
  return `Sign in to ${brandName}`;
}

export function magicLinkText(
  brandName: string,
  url: string,
  ttlSeconds: number,
): string {
  return [
    `Use this link to sign in to ${brandName}:`,
    "",
    url,
    "",
    `This link expires in ${formatDuration(ttlSeconds)}.`,
    "If you did not request this email, you can ignore it.",
  ].join("\n");
}
```

const secure = config.tls === "tls";
